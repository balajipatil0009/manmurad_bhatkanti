# Taste
- Prefers the homepage header to be transparent (bg-less, white text) overlaying a full-viewport hero, while all other pages use a solid/semi-opaque sticky header — i.e. per-page header treatment rather than one global style. Confidence: 0.65
- Prefers the hero section itself to fill the whole viewport (`min-h-screen`) with the nav overlaying it, rather than subtracting the navbar height from the hero or adding a top margin/offset to push content below the nav. Confidence: 0.6
- Specifies colors by named design tokens defined as CSS variables (e.g. `var(--color-forest)` / `bg-forest`) instead of hardcoded hex or arbitrary values. Confidence: 0.7
- Expects text/icons on a dark or colored solid header to be explicitly white so contrast holds, and expects unused color-state logic to be deleted once a single treatment is chosen. Confidence: 0.55
- Wants the main menu links rendered inline in the desktop navbar (visible between logo and CTA) rather than hiding all navigation behind a burger at every breakpoint; the burger menu is for mobile/tablet only. Confidence: 0.6
- Expects menu links that name a category/filter (e.g. "Night Treks", "Backpacking Tours") to deep-link to the pre-filtered results (`/trips?category=night-trek`), not all land on the same unfiltered listing page. Confidence: 0.75
- When a value is duplicated between hardcoded code defaults and CMS seed data (e.g. seeded `trekLinks`), expects both to be updated together so a re-seed doesn't reintroduce the old behavior. Confidence: 0.6
- Expects behavior claims to be verified against the running built app (start server, hit the actual URLs, confirm the expected results), not just typecheck/lint/build passing. Confidence: 0.55
- Prefers the agent to actually execute the setup/maintenance commands it recommends (apply migrations, run seed, re-run after fixing a blocker) instead of only handing back a list of commands to run manually. Confidence: 0.5
- When a fix is applied to one admin-editable content type, expects it applied consistently to every other comparable one in the same pass (asking "did you apply this to all things we edit from the admin panel?"), not just the single reported case. Confidence: 0.7
- Prefers repeated per-config logic (e.g. identical hooks on many collections/globals) consolidated into one shared helper/module rather than copy-pasted into each file. Confidence: 0.55
- Expects the project to be audited for production/deployment readiness (image `remotePatterns` for blob storage, upload size vs host body limits, secret/env fallbacks, migrations in the deploy step, tracked junk/large assets), not just for local dev correctness. Confidence: 0.55
- Gives terse, often ungrammatical one-liners ("do it", "is amm things are optimized for production ?", "in the section we have to support the video or iamge any of both can we do that ?") and expects the agent to infer the full scope and act/present findings without asking clarifying questions; may simply not answer a multiple-choice clarifying question, so pick the sensible default and proceed. Confidence: 0.5
- For CMS content changes (e.g. replacing a media file in the admin panel) prefers to do those steps themselves, and when they do, wants an explicit numbered "here's exactly what to do now" checklist naming the admin screen, the item, and the expected result — rather than an open-ended "want me to do it?" question. Confidence: 0.55
